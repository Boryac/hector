# DEMO_SCRIPT.md — 演示录屏分镜（2–3 分钟）

> 真实运行的证据在 `docs/demo.md`（任务 ID、节点明细、事件构成、报告产物）。
> 本文只写**怎么录**，不重复数据。
>
> 前置：`upstream/hector` 下 `./bin/researchos.exe all` 已启动，
> 浏览器打开 `http://127.0.0.1:8080/`，Token 已填入页面顶部输入框。

## 演示任务原文

> 研究全球 AI Agent 开源生态，筛选 10 个代表性项目并生成竞争分析报告

一句固定不变，方便对照 `docs/demo.md` 里的实测数据。

---

## 分镜

### 0:00–0:20 提交研究目标
- 镜头：Dashboard 新建表单。
- 动作：粘贴研究目标，深度选 `standard`，最大并发 4，勾选交叉验证，点提交。
- 讲解要点：默认值已给合理配置；任务此时是 `awaiting_approval`，不是自动开跑。
- 画面对照：状态标签显示「待批准」。

### 0:20–0:40 生成工作流
- 镜头：任务详情页画布。
- 动作：点「批准」。画布上节点逐个出现（search → analyze ×3 → verify → synthesize）。
- 讲解要点：计划是启发式生成的（未配置 LLM 时），`synthesize` 必须是唯一收尾节点。

### 0:40–1:10 并发执行
- 镜头：左侧节点时间线 + 下方事件流。
- 动作：不剪辑，让事件自然滚动。
- 讲解要点：三条检索分支同时跑，事件类型是 `node.started` / `tool.invoked` /
  `tool.completed` / `node.progress` / `evidence.created`，全部来自真实执行。

### 1:10–1:40 来源与证据
- 镜头：切到来源区，展开 2–3 条资料的详情。
- 动作：指一条 wikipedia、一条 github，展示站点、Provider、可信度、抓取状态。
- 讲解要点：39 条来源里 18 条抓到正文，抓不到的会写 `robots_blocked` 或
  `fetch_failed` 并给出原因，不假装成功。

### 1:40–2:10 故障注入与恢复
- 镜头：另开终端，`tasklist` 找到 worker 的 Windows PID 后 `taskkill /F /PID`。
- 动作：回浏览器，节点卡在 `running`；等租约过期（默认 3 分钟，演示可先设
  `RESEARCHOS_STALE_LEASE=40s`）；重启 worker，节点自动被接管并跑完。
- 讲解要点：已完成节点不会被重跑，只有被打断的那个节点 `attempts` 加一。
  一条命令就能复现：`bash scripts/fault-injection.sh`（实测 PASS）。

### 2:10–2:40 报告与引用
- 镜头：报告区。
- 动作：点核心发现里的 `[3]`，跳到「信息来源」第 3 条；点导出 Markdown / HTML。
- 讲解要点：引用编号与来源条目一一对应；导出走带 `Authorization` 头的 fetch，
  Token 不会出现在 URL 里。

### 2:40–3:00 收尾：说清楚边界
- 镜头：`docs/benchmark.md` 的「未实测项」表格。
- 讲解要点（必须讲，不要跳过）：
  - 未配置 LLM，结论由规则从原文抽取，质量上限是「能逐字引用的句子」，
    做不到「筛选 10 个项目并做竞争分析」这种需要判断的产出；
  - Docker Compose 未在本机验证（本机未安装 Docker）；
  - 单用户本地形态，共享密钥固定 Subject，因此不做多用户。

## 录制约束

1. **不得用静态图冒充运行**：所有状态变化必须是真实点击/真实事件流。
2. **不得剪辑掉失败**：如果这次跑出现 `failed` 或 `skipped`，保留并在讲解里说明原因。
3. 终端窗口字号调到 16pt 以上，命令逐字敲或粘贴后回车，不要预置好结果再展示。
