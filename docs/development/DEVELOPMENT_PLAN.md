# DEVELOPMENT_PLAN.md — 12 周里程碑（每周一个可验证交付物）

## Phase 0：基础审查与项目初始化（第 1–2 周）
任务：Fork Hector、独立分支、源码架构梳理、核查 Issue #2 身份隔离、审查 A2A 认证与用户上下文传递、
检查任务队列 / Checkpoint / 恢复逻辑、建立 Go 与前端测试基线、确定数据库模型与 API 契约。
交付：docs/hector-audit.md（架构分析）、docs/security-review.md（安全审查记录）、
docs/mapping-table.md（二次开发差异清单：保留/修改/新增/替换）、可运行开发环境。
**通过门槛：人工确认安全审查结论后，方可进入 Phase 1。**

## Phase 1：产品工作台（第 3–4 周）
任务：Dashboard、研究任务创建、任务详情、前后端 API 契约落地、SSE 接入、基础工作流画布、真实节点状态展示。
交付：用户可创建研究任务，查看任务结构和真实执行状态（非模拟）。
验收：创建 → Planning 状态变化有真实事件；画布节点与后端状态一致；断线重连能续接。

## Phase 2：自主研究执行（第 5–6 周）
任务：Planner（结构化输出 + Schema 校验）、任务拆解、Agent 动态分配、DAG 编译、多 Agent 并发执行、
执行状态持久化、节点级错误处理。
交付：一个研究任务可拆解为多个真实 Agent 子任务并行执行。
验收：Planner 输出可校验；DAG 依赖正确（并行节点确实并行、依赖节点确实等待）；节点失败可重试。

## Phase 3：搜索与证据系统（第 7–8 周）
任务：多搜索 Provider（可插拔接口 + 至少 1 个真实 Provider + 1 个 Mock Provider）、网页抓取、
正文解析、URL 规范化、去重、来源管理、结论与来源关联、交叉验证。
交付：Agent 能从互联网收集资料，并生成可追溯的研究证据。
验收：同一 URL 重复抓取只留一条；证据状态有真实 source 支撑；冲突结论被标记 Conflicting 而非掩盖。

## Phase 4：报告与交互完善（第 9–10 周）
任务：报告结构、报告生成、引用跳转、Markdown 导出、PDF 导出、节点详情、失败重试、暂停与恢复、MCP 工具管理完善。
交付：用户能完成一次完整研究并获得结构化报告。
验收：报告 9 节齐全；引用点击可到 Source；暂停后恢复能从 Checkpoint 继续而非重头；PDF 非空且内容与 Markdown 一致。

## Phase 5：测试、部署与发布（第 11–12 周）
任务：Go 单元测试、API 集成测试、前端 E2E 测试、多任务压力测试、任务中断恢复测试、权限隔离测试、
Docker Compose 部署、开发文档、README 与演示视频。
交付：可独立部署的 Hector ResearchOS V1.0。
验收：见 TESTING_AND_ACCEPTANCE.md 全量检查 + 最终演示任务全程跑通。

## 开发顺序（再次强调，Codex 不得颠倒）
1. 定义真实数据模型 → 2. 最小可运行执行链（创建、执行节点、保存状态、输出事件）
→ 3. 前端可视化（映射真实事件）→ 4. 扩展研究能力（搜索、验证、MCP、报告）。
