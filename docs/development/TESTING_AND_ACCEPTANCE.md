# TESTING_AND_ACCEPTANCE.md — 测试与验收（全部通过才算 V1.0）

## 产品功能验收（逐项打勾）
- [ ] 用户能创建研究任务；系统能自动生成研究计划（结构化）。
- [ ] 系统能执行多个 Agent 子任务；前端能展示真实 DAG。
- [ ] 用户能查看 Agent 运行详情（模型、工具、Token、日志）。
- [ ] 系统能收集并管理网页来源；报告能关联具体引用来源且可跳转。
- [ ] 用户能暂停、恢复、取消任务；能查看历史研究结果。
- [ ] 用户能导出 Markdown 和 PDF 报告。
- [ ] Worker Pool 并发上限可配置；任务状态持久化；节点失败按策略重试；支持 Checkpoint 恢复；
      API 与 Worker 可独立启动；事件有唯一 ID 与可追溯时间；关键路径接 OpenTelemetry；
      外部工具调用有超时与错误隔离。

## 性能与稳定性（首轮目标，必须实测，不得直接宣传）
| 指标 | 目标（待验证） | 实测方法 |
|---|---|---|
| 同时运行研究任务 | ≥5 | T5.4 压力脚本，记录成功率与耗时 |
| 单任务并发 Agent | 可配置，默认 4 | 配置改动后重测 |
| 前端执行状态更新延迟 | P95 ≤2 秒 | SSE 时间戳采样 |
| 任务状态持久化 | 关键状态变更可追溯 | kill 后查 DB 与事件 |
| 单节点失败恢复 | 通过故障注入测试 | T5.3 |
| API 健康检查 | 正常部署下可用 | /health 分级检查 |
| 重复事件处理 | 幂等 | 重放同一 event_id 两次 |
| 关键模块单元测试 | ≥80% 覆盖率目标 | go test -cover，有断言 |

覆盖率是目标，不应为数字写无断言测试。未达标要在 benchmark 里如实写原因与后续计划，
不得编造数字。

## 专项测试清单
- 单元：Planner Schema 校验、DAG 环检测、URL 规范化、去重哈希、证据状态机、重试策略。
- 集成：创建→规划→执行→证据→报告全链路；SSE 续接；暂停/恢复；节点重试。
- E2E：前端创建任务、看画布、看证据、看报告、导出 PDF。
- 故障注入：kill -9 Worker 进程、断 DB 重连、工具超时、搜索 Provider 失败。
- 安全：伪造 user_id 隔离、Prompt Injection 注入页、高风险工具审批、路径穿越导出、Key 掩码。
- 压力：5 并发任务、长任务不阻塞 API、事件不丢不重。

## 最终演示验收（必须用真实任务，不得用写好的静态报告冒充）
演示任务原文：
> 研究全球 AI Agent 开源生态，筛选 10 个代表性项目并生成竞争分析报告。

演示必须包含：创建任务 → Planner 自动拆解 → DAG 自动生成 → 多 Agent 并发运行 →
搜索结果实时出现 → 资料进入来源中心 → 证据验证过程可查看 → 报告逐步生成 →
报告引用可跳转 → 人为终止一个 Worker，验证任务能够恢复。
最终结果是一个可运行、可观察、可验证的产品，而不是一组静态页面。
演示视频分镜见 DEMO_SCRIPT.md，成片链接写入 docs/demo.md。
